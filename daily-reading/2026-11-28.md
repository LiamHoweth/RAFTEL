## What to borrow: change only the requested result

ManipScope's authors replay the same simulated initial state with different requested objects. Some evaluated checkpoints repeatedly choose the same object despite a changed instruction, including on familiar task scenes. That result is about the tested policies, not RAFTEL. The useful experiment design is to change the goal without changing the starting layout.

For an offline BenchSort follow-up, keep one explicit scene and the three bin positions unchanged. In a second config, swap the category labels assigned to two bins. Predeclare the expected destinations separately from the scorer and compare each run's reported mock placement coordinates against them. The swapped categories should move to the newly assigned bins; the untouched category should stay put. A fixed-destination baseline should fail the swapped case. This checks routing configuration, not language understanding, grasping, or physical placement.
