# RAFTEL daily reading

A short reading room for staying current without losing focus on the build.

**[Latest briefing: November 11, 2026](2026-11-11.md)**

## Current focus

Start with the full-range arm on a clamped stand, picking up objects and sorting them into boxes. Keep the later mobile home-assistant goal in view without letting it expand the first milestone.

This focus comes from the project owner's stated plan. As the repository fills out, its design documents, code, tests, hardware choices, and `nextSteps.md` should make each briefing more specific. The reading room complements that roadmap; it does not replace or edit it.

## What each briefing covers

1. **Read first:** the two or three items most likely to improve the next project decision.
2. **What changed in RAFTEL:** relevant commits, design decisions, open issues, and blockers, with repository links.
3. **What other teams are doing:** company releases and research, with a clear explanation of what to borrow, compare, or defer.
4. **Practical takeaway:** a small experiment, question, or decision connected to the current milestone.
5. **Sources and limits:** original links, publication dates, verification date, and any missing evidence.

Aim for a five-minute read. Fewer strong items are better than a padded news feed.

## Editorial rules

- Review the full current repository structure and relevant project files before selecting stories. Read newly added or changed material, not just the last briefing.
- Prioritize the current milestone and `nextSteps.md` when it exists. Distinguish stated plans, implemented behavior, and suggestions.
- Prefer original documentation, release notes, papers, and company announcements. Label company-reported results and distinguish demos from measured reliability.
- Date each source. Separate recent news from older background, and do not present a familiar story as new without a material change.
- Connect each item to an actual project choice. Do not assume a robot, motor, camera, software stack, budget, or compute setup that the project has not selected.
- If nothing important changed, publish a short dated “no material update” note with what was checked. Do not invent news.
- Keep dated entries as an archive. Preserve manual additions and clearly label substantive corrections.
- Keep updates inside `daily-reading/`. The root README link is the entry point; leave implementation, hardware configuration, and the roadmap untouched.
