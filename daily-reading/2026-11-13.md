## What changed in the repository

### Merged: a repeatable Mac workflow

[PR #20](https://github.com/LiamHoweth/RAFTEL/pull/20) merged November 12. The [Mac guide](../docs/mac-setup.md), root [Makefile](../Makefile) and [verification script](../scripts/verify.sh) now provide one place to run setup, the logical demo, seeded evaluation, engineering studies and full portable checks.

The [setup receipt](../docs/mac-setup-2026-11-12.md) records **2,200 passing tests** on the Mac, CLI checks and a fresh offline wheel. All eight Linux/Windows Python 3.11–3.14 jobs also passed on the [merged snapshot](https://github.com/LiamHoweth/RAFTEL/actions/runs/43278698906), verified today. Some handoff prose still describes the pre-merge checkpoint; GitHub confirms the PR is merged.

The reused native FreeCAD environment completed changed recompute for **53 documents / 3,001 objects**, preserving all 703 checked source/copy/addon files. Its shape scope was `none`: this checks restoration and object state, without repairing original Art1 history or establishing whole-shape validity. Robot models and business logic were unchanged by setup.

**Useful now:** on the configured Mac, use `make demo` or `make benchmark` for a quick logical check, and `make verify` when full verification is needed. The latter retains a fresh local evidence directory. No speculative ROS, camera or learning stack is needed for those commands.

## One relevant industry update

**NTT, November 11:** NTT announced a world model that evaluates candidate robot actions for outcomes such as drops and load collapse before choosing an action. The company reports shelf-loading success improving from **73.1% to 92.3%** in a small-robot experiment. Airport-baggage trials with Mujin are planned, not demonstrated production deployment. [Primary announcement](https://group.ntt/en/newsrelease/2026/11/11/261111b.html), checked November 13.

**What to borrow, as an engineering inference:** keep proposed actions, predicted outcomes and observed outcomes separate. For BenchSort, document why a candidate passes or fails the available checks, then test those predictions against physical observations when the hardware is ready. Existing nominal geometry and logical scoring cannot supply that physical evidence.

The release provides no verified ready-to-integrate implementation for Thor, and its reported percentage is not comparable to ARM-01's logical benchmark. No new model dependency is recommended. Yesterday's PRISM and Gemini Robotics items remain in the [November 12 briefing](2026-11-12.md); they are not repeated as new news.

## Practical takeaway

Before another full-batch attempt, collect the **exact failed filename, actual settings, filament label and first-layer photographs** for the existing adhesion procedure. Keep the original output unchanged so any diagnostic result can be compared with it. If using the Mac meanwhile, the new local commands make software checks easier without implying a hardware milestone.
